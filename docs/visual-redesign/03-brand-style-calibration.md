本轮因此不再扩展方向数量，只校准原 A。

## 1. 修订后的主方向

### Editorial Clarity × Human Observation

**中文：编辑式清晰，人本式观察。**

Swiss 是底层构图与 token 约束，不再作为最终风格名称。最终方向由两个可见行为组成：

- **编辑式清晰：** 每一屏明确选择一个主角；删掉无效标签、虚构期号和装饰性系统语言；用标题、图像、摘要和元信息的真实权重表达判断。
- **人本式观察：** AI 不被画成一个物体；它通过人的处境、正在进行的动作、真实界面与结果变化出现。人物不是装饰，截图不是填充，批注不是造型。

### 1.1 为什么适合 Midimily

Midimily 同时服务企业 AI 落地与个体 AI 成长，两类用户都带着具体的不确定性来到网站：从哪里开始、哪件事值得先做、如何判断一次尝试是否有效。网站最有价值的能力是把复杂内容做出取舍，并把抽象讨论落到一个真实小闭环。

“编辑式清晰”让用户先看到结论、证据和下一步；“人本式观察”让专业判断来自真实处境，而不是抽象图标。它与 `PRODUCT.md` 中“清楚、温暖、务实”的人格一致，也能保留方案库、Web Deck、GEO 证据路径与企业 / 个体双入口。

### 1.2 与普通 AI 新闻站的区别

- AI 新闻站通常按发布时间和热点组织首页；Midimily 按“问题—尝试—结果—下一步”组织。
- 新闻站强调事件数量与更新速度；Midimily 一屏只突出一个被编辑选择的实践或判断。
- 新闻站常用产品 Logo、发布会图和标题流；Midimily 必须补上人与工作情境、界面证据或结果变化。
- Midimily 不使用 `Latest`、`Trending`、`Insight` 等英文微标签制造栏目感，除非它们是真实、长期维护的栏目名称。

### 1.3 与 SaaS 官网的区别

- SaaS Hero 常用“价值承诺 + 说明 + 两个按钮 + 右侧产品图”；Midimily 首屏先给出一个明确判断，再把企业 / 个体作为两条文字路径呈现。
- SaaS 用功能卡和图标解释产品；Midimily 用真实案例、人物处境、工作界面与过程证据解释方法。
- SaaS 把每一段都做成转化模块；Midimily 允许阅读停顿，CTA 只在用户已经理解下一步的位置出现。
- Midimily 不使用定价卡、功能矩阵、假评分、设备 mockup 或产品状态面板。

### 1.4 与传统科技媒体的区别

- 传统科技媒体的核心产品是报道；Midimily 的核心产品是从报道、方法与案例中给出可开始的行动。
- 传统媒体的作者和时间通常是主要可信线索；Midimily 还必须展示实践对象、采取动作与结果证据。
- 传统媒体可以停在“发生了什么”；Midimily 的详情页需要继续回答“这对谁有用、第一步是什么”。
- Midimily 的企业 / 个体服务入口和 Web Deck 是行动路径，不能退化为新闻栏目或普通文章归档。

### 1.5 用户浏览 10 秒后应留下的三个视觉印象

1. **一个明确的中文判断。** 首屏不是口号墙，只有一句能复述的主张：“不只看趋势，先跑一个小闭环。”
2. **一个真实的人或工作情境。** 用户能看到谁在什么场景中使用技术，而不是看到机器人、节点或抽象光效。
3. **一处有内容依据的蓝色批注。** 蓝色指出“为什么值得看”或“下一步是什么”，不铺成背景、不变成发光装饰。

### 1.6 遮住 Logo 后仍应识别 Midimily 的特征

- 首页与文章都使用“问题 / 观察—真实证据—可开始的一步”的固定叙事顺序。
- 人物或工作情境与真实界面截取在同一画面并置，明确显示“技术进入了哪件事”。
- 蓝色批注只表达编辑判断、证据说明或下一步，且一屏最多一处。
- 同屏只有一个绝对视觉主角，其他信息明显退后；不出现连续等重卡片。
- “企业的 AI 落地顾问，个体的 AI 成长伙伴”和“小闭环”保持自然中文表达，不被英文标签或系统术语覆盖。

### 2.4 风险结论

原 A 已经排除了渐变、发光、玻璃、机器人与连续卡片，基础方向正确；真正的高风险集中在三点：

1. **黑白蓝 + 大字 + 细线容易形成新的通用模板。**
2. **虚构 Issue 与过量编号会把普通内容包装成期刊系统。**
3. **“知识切片 / 路径”如果没有真实数据关系，会把内容站说成知识机器。**

因此本轮删除虚构期号，降低编号和结构线的默认权重，并把品牌识别从“排版造型”转移到“人、真实界面、编辑判断”的稳定组合。

## 3. 非 AI 美学原则

以下 8 条均为后续静态样板和组件实现的硬性检查项。

### 原则 1：一屏一主角

- **具体规则：** 每个视口只允许一个内容获得最大字号、最大图像面积或最高对比度；三者不能分别被三个对象占用。
- **正确表现：** 首页首屏以一句主张为主角，路径链接和批注明显退后；文章区以一篇主稿为主角。
- **错误表现：** 大标题、亮蓝按钮、人物大图和三张卡同时争抢注意力。
- **Codex 落地判断标准：** 截取任意 1440×900 或 390×844 画面，若无法在 2 秒内指出唯一主角，则不通过。

### 原则 2：蓝色必须表达判断

- **具体规则：** `#002FA7` 只用于编辑判断、文本链接、当前状态和关键标记；不用作大面积背景、渐变端点或装饰色块。
- **正确表现：** 一条蓝色批注解释主稿为何值得读，链接使用同色并有非颜色状态。
- **错误表现：** 整屏蓝底、蓝色发光按钮、每个编号和边框都变蓝。
- **Codex 落地判断标准：** 对每个蓝色区域提出“它表达什么状态或判断”；无法回答即移除。单屏蓝色可见面积原则上不超过约 10%。

### 原则 3：图像必须提供证据

- **具体规则：** 图片至少提供人物、场景、真实界面、结果物或事件线索之一；不得只填满比例框。
- **正确表现：** 人物在实际工作场景中，旁边显示其使用的真实界面局部或产出。
- **错误表现：** 通用办公室、抽象几何、机器人、发光物体、与文章无关的氛围图。
- **Codex 落地判断标准：** 删除图片后若文章理解完全不受影响，且图片没有人物 / 情境价值，则图片不得进入样板。

### 原则 4：编号必须可追溯

- **具体规则：** 编号只对应真实步骤、日期、Deck 页码或长期栏目序列；不为排版气质虚构 `Issue`、章节号或路径号。
- **正确表现：** `第 2 / 8 页`、实施步骤 `1–4`、真实发布日期。
- **错误表现：** 把企业和个体入口命名为 `ISSUE 01 / 02`，或给三篇普通文章随意编号。
- **Codex 落地判断标准：** 每个编号必须能回答“由谁维护、顺序依据是什么、下一项是什么”；任一问题无答案即删除。

### 原则 5：容器不是默认答案

- **具体规则：** 只有可独立操作、可复用或需要明确边界的对象才使用容器；圆角只用于交互对象，不用于所有文章和 Section。
- **正确表现：** 主文章以图文版面出现，次要文章用分隔列表，按钮有清楚触控边界。
- **错误表现：** 标题、摘要、人物、步骤和 CTA 各自套卡，卡内再套卡。
- **Codex 落地判断标准：** 单屏完整包边容器不超过 2 个；首页前三屏不得连续出现相同卡片骨架。

### 原则 6：中文承担信息，英文不填空

- **具体规则：** 页面以自然中文命名栏目和动作；英文只用于真实产品名、通行技术名或正式品牌资产。
- **正确表现：** “企业 AI 落地”“查看方案”“AI Agent 的适用边界”。
- **错误表现：** `FEATURED INSIGHT`、`HUMAN OBSERVATION 01`、`// INTELLIGENCE LAYER` 等可删除微标签。
- **Codex 落地判断标准：** 删除英文后信息不变，则删除；标准动作不得被主题化英文替代。

### 原则 7：不对称服务于阅读顺序

- **具体规则：** 页面可局部不对称，但标题、摘要、正文和行动必须沿稳定阅读轴排列；不能为了打破网格而随机错位。
- **正确表现：** 主稿跨 7 栏，次稿位于同一基线侧栏，视线自然从主稿进入次稿。
- **错误表现：** 图块悬浮、文字跨轴跳跃、移动端保留桌面错位。
- **Codex 落地判断标准：** 关闭颜色与图片后，纯文本阅读顺序仍清楚；移动端 DOM / 视觉顺序一致。

### 原则 8：动效只确认关系或状态

- **具体规则：** 动效用于链接状态、内容展开、Deck 翻页或明确的前后关系；每屏最多 1–2 个运动对象，触控操作不依赖 Hover。
- **正确表现：** Focus / Hover 用下划线与颜色确认链接；Deck 翻页给出短促方向反馈。
- **错误表现：** 卡片上浮、粒子、轨道自转、鼠标光斑、滚动淡入整页内容。
- **Codex 落地判断标准：** 动效关闭后信息与操作完全保留；支持 reduced-motion；任何关键操作在 390px 触控环境可直接发现。

## 4. Midimily 核心视觉母题

本方向只保留三个母题。**知识切片、时间痕迹、信息折页和内容索引不作为独立母题**；只有当真实内容需要时，才作为普通排版工具出现。

### 4.1 编辑批注

1. **品牌含义：** Midimily 不只是收集内容，而是指出一个真实问题为什么重要、哪里值得先做。
2. **为什么属于 Midimily：** “先跑一个小闭环”本身就是编辑选择；批注把这种判断从文案变成跨页面可见行为。
3. **首页：** 首屏最多一处蓝色短批注，解释主张或指出两条服务路径的选择条件。
4. **文章卡片：** 只在主稿出现一句不超过 22 个汉字的选择理由；次稿不重复批注。
5. **文章详情页：** 在导语或首个关键证据旁出现；正文长文每 3–4 个视口最多一处。
6. **文章封面：** 可用一个蓝色框、短线或箭头指向真实细节；不覆盖人物面部和产品关键信息。
7. **频率上限：** 每屏 1 处；单篇长文最多 3 处。
8. **移动端简化：** 从页边移到相关内容下方，以一条蓝色左线和短句呈现；不做浮动标注。
9. **禁止场景：** 没有实际判断、证据或下一步时；仅为了填空、平衡构图或显示蓝色时。

### 4.2 人物与技术并置

1. **品牌含义：** AI 的价值发生在人、任务和结果之间，技术不能脱离使用者独自成为主角。
2. **为什么属于 Midimily：** 企业落地与个体成长都从人的实际不确定性开始，这比通用 AI 符号更贴近品牌承诺。
3. **首页：** 选一个真实人物 / 工作场景与一个真实界面或成果局部形成同一叙事，不使用左右各占一半的产品 Hero 模板。
4. **文章卡片：** 人物文章优先显示带环境的肖像；技术证据通过小型局部裁切或图注出现，不做两张等重拼贴。
5. **文章详情页：** 标题后先交代人物 / 场景，再展示工具或界面；图注说明二者的具体关系。
6. **文章封面：** 人物占主要面积，界面或成果只作为真实局部进入；不得把人处理成数字化、全息化肖像。
7. **频率上限：** 首页前三屏最多 1 组；单篇文章封面与正文合计最多 2 组。
8. **移动端简化：** 先人物 / 场景，后证据局部，垂直排列；不缩成难以辨认的双栏拼图。
9. **禁止场景：** 无授权人物、摆拍图库、无法说明人物与技术关系、为了“有人味”随意放手部或背影时。

### 4.3 真实界面截取

1. **品牌含义：** Midimily 讨论的技术已经进入一件具体任务，并产生可检查的过程或结果。
2. **为什么属于 Midimily：** 方案库与 Web Deck 的价值在于可执行证据；真实界面比机器人、节点或抽象系统图更能证明这一点。
3. **首页：** 只截取一个与主观点直接相关的界面 / 输出局部，配一句“看什么”的图注；不展示完整产品墙。
4. **文章卡片：** 只有当截图在小尺寸仍能识别关键变化时才使用；否则用标题和文字，不放缩小截图。
5. **文章详情页：** 可作为封面后的第一证据，保留必要上下文并标出关键区域；敏感信息必须处理。
6. **文章封面：** 使用原始界面平面裁切，不套电脑 / 手机壳，不做夸张透视；允许一处蓝色标记。
7. **频率上限：** 首页前三屏最多 2 张；单篇文章按论证需要使用，不连续出现 3 张无解释截图。
8. **移动端简化：** 裁切到一个关键区域并配独立图注；完整界面可提供点击放大，但核心信息不能依赖放大后才理解。
9. **禁止场景：** 界面属于未公开产品、包含敏感数据、截图无法支持文章论点，或只是为了证明“这里在谈软件”时。

### 明确禁止的视觉母题

AI 大脑、机器人、芯片、电路线、发光球体、宇宙、神经网络、数据流、全息界面、通用未来城市与无意义几何抽象均不得进入主视觉、封面或背景。小米立是品牌陪伴资产，不是 AI 的替身；它只在联系、引导或低干扰陪伴场景出现。

## 5. 图像语言

图像系统的判断顺序是：**真实证据 > 真实情境 > 有依据的编辑图解 > 受限的生成式插图 > 无图。** 无合适图像时允许纯排版，禁止为了填满版面制造氛围图。

### 5.1 人物文章

- **来源优先级：** 优先使用已获授权的真实人物照片，其次是可验证的现场记录；不以生成式人物替代真实受访者。
- **裁切：** 主比例为 4:5，保留眼神、手部动作或工作对象中的至少两项；不只裁一张无情境大头照。
- **背景：** 原则上保留能说明职业、地点或任务的背景；只在背景泄露隐私或明显干扰主题时弱化。
- **编辑标记：** 每张图最多一处蓝色短线 / 框与一条不超过 16 个汉字的事实说明，不在脸部绘制标记。
- **禁止处理：** 不数字化皮肤、不叠代码、不做双重曝光、不生成发光轮廓、不把人物变成 AI 风格数字肖像。

### 5.2 产品新闻

- **来源优先级：** 真实产品界面、设备、官方 Logo 与实际使用场景优先；Logo 只能说明主体，不能单独承担整张封面。
- **截图裁切：** 保留足以理解功能变化的上下文，再裁掉浏览器空白、无关菜单和敏感数据；图注说明版本、功能或变化点。
- **设备 mockup：** 不允许透视悬浮设备 mockup；只有设备物理形态本身是新闻对象时，才使用正视或真实场景照片。
- **避免发布会海报感：** 不放大 Logo、不铺品牌渐变、不用“震撼发布”式大字；把焦点放在功能如何改变人的任务。

### 5.3 概念文章

- **抽象图形：** 只允许表达可命名关系的线、面、对照或步骤；每个形状在图注中都能解释。
- **抽象程度上限：** 读者在不读正文时，应能判断图形是在表达比较、顺序、范围还是因果；若只能感到“技术主题”，抽象度过高。
- **隐喻：** 允许使用来自真实工作与日常经验的单一隐喻，如草稿与成品、入口与出口、问题清单与完成项；不用宇宙、脑、网络或能量隐喻。
- **论点关系：** 每幅图只支撑一个文章论点；图注必须明确说明对应段落，不制作可替换到任何 AI 文章的通用插图。

### 5.4 趋势与观点文章

- **编辑判断：** 封面可出现一句核心观点，但必须是文章真实结论，不是从标题再缩写一次。
- **线索选择：** 至少使用数据、时间、人物或事件中的一项真实线索；来源在正文或图注中可追溯。
- **文字控制：** 核心观点不超过 22 个汉字，不与文章主标题重复。
- **避免金句海报：** 不把大字居中铺满纯色背景，不加引号、作者头像和分享按钮组合；观点应与证据图、人物或事件材料共同出现。

### 5.5 全局图像规范

| 项目 | 规则 |
|---|---|
| 图片比例 | 人物 4:5；实践 / 场景 3:2；界面 / 成果 4:3；小型列表可使用 1:1，但同一列表不得混用比例 |
| 图片中文字上限 | 普通照片 0–16 个汉字且仅一处；趋势观点最多 22 个汉字；图解最多 3 个短标注，长解释进入图注 |
| 色彩数量 | 页面 UI 保持白 / 中性浅灰 / 近黑 / 单蓝；图片保留真实色彩，不强行统一蓝色滤镜。编辑叠加只允许蓝色和白 / 黑中的一种 |
| 留白规则 | 图像内部留白必须来自真实构图或为一处必要标注服务；不得为放大标题制造大片空背景 |
| 渐变 | 不允许作为封面背景、叠层或氛围；真实摄影中的自然光线变化不视为渐变效果 |
| 阴影 | 图片本身不加装饰阴影；浮层放大如有功能需要，仅用边框或页面层级处理 |
| 3D | 不允许生成式 3D、等距设备、悬浮 UI 或光滑抽象物；真实产品本身为 3D 物件时可使用纪实照片 |
| 生成式插图 | 允许但必须是最后选择，且不能冒充真实人物、真实界面、真实事件或真实数据 |

生成式插图必须同时满足：

1. 文章概念无法通过授权照片、真实界面、成果物或简单编辑图解表达；
2. 不包含本文件禁止的 AI 符号与无意义几何；
3. 只表达一个可命名论点，图中每个主要元素都能被解释；
4. 使用不超过 3 个主色，且不使用渐变、发光、玻璃、3D 塑料质感；
5. 不生成可被误认为真实人物、真实产品或真实现场的内容；
6. 图像中文字仍遵守上限，并由页面排版承担主标题；
7. 在 390px 宽度下仍能辨认主信息；
8. 上线前由编辑确认它无法被无损替换到另一篇普通 AI 文章。

## 6. 三个样板区域的非模板化布局原则

### 6.1 首页首屏

| 判断项 | 规则 |
|---|---|
| 结构描述 | 顶部导航之后，先出现一条全宽但不铺满视口的中文主张；下方同一阅读轴放一段解释和企业 / 个体两条文字路径。真实人物 / 场景与界面证据作为主张之后的第一块材料，而不是右侧装饰图。 |
| 第一视觉主角 | **观点**：“不只看趋势，先跑一个小闭环。”品牌名、文章和图像都退居其后。 |
| 是否使用 Hero 大图 | 不使用占满首屏的 Hero 大图。可在首屏下沿露出一张有证据价值的 3:2 图像，让用户知道下一屏将进入真实实践。 |
| 是否展示多篇文章 | 不展示文章阵列；最多展示一个真实实践入口，不出现轮播与三篇推荐。 |
| 内容上限 | 1 条主张（建议不超过 24 个汉字）、1 段解释（不超过 56 个汉字）、2 条服务路径、1 处批注、1 个实践入口。 |
| 视觉焦点 | 主张拥有最大字号；蓝色只标一处编辑判断；服务路径以可点击文字而非两个厚重按钮呈现。 |
| 避免 SaaS Hero | 不使用“左文右图 + 两个按钮”、右侧产品 mockup、客户 Logo 墙、指标、评分、视频播放键或漂浮功能卡。 |
| 禁止模式 | 超大英文眉题、虚构 Issue、机器人网络、渐变、玻璃、三个入口卡、双主 CTA、自动轮播、鼠标跟随效果。 |
| 桌面差异 | 允许主张占 7–9 栏，解释与路径沿下方基线展开；证据图像从首屏下沿进入，不形成对称二栏。 |
| 移动差异 | 第一屏只保留主张、短解释和两条服务路径；批注压缩为一句蓝色短句。图像移到第一屏之后，触控目标至少 44px，不依赖 Hover。 |

### 6.2 首页文章区第一屏

| 判断项 | 规则 |
|---|---|
| 结构描述 | 允许“一主两次”，但不是三个卡片：主稿由图像 + 标题 + 一句选择理由组成；两篇次稿以文字列表出现，其中最多一篇带小图。 |
| 是否采用卡片 | 主稿和次稿默认不加完整容器。只用局部规则线分组；可点击区域通过链接状态、间距与 Focus 表达。 |
| 内容权重 | 主稿占可见面积约 60–70%；两篇次稿共享余下空间，且字号、图像面积和摘要长度明显更小。 |
| 编辑选择 | 主稿旁只有一处蓝色批注，说明它为何与“真实小闭环”有关；不用 `Featured` 或虚构编号。 |
| 避免规则网格 | 不采用三列等宽、六宫格或 Bento；主稿和次稿的起始基线可错开，但阅读轴稳定。 |
| 主角关系 | 有高信息图像时图像是主角、标题第二；没有可靠图像时标题是主角，不生成占位图。摘要永远不与标题争抢。 |
| 内容上限 | 1 篇主稿 + 2 篇次稿；主稿摘要最多 2 行，次稿各最多 1 句；每篇最多显示日期或栏目中的一个元信息。 |
| 禁止模式 | 三张等大封面、每篇多个标签、Hover 上浮、统一圆角卡、按钮“查看详情”重复三次、滚动依次淡入。 |
| 桌面差异 | 主稿可占 7–8 栏，次稿形成 4–5 栏文字侧列；不要求上下等高。 |
| 移动差异 | 顺序为主稿图 / 标题 / 批注 → 次稿 1 → 次稿 2；次稿不强制缩略图，三者之间用留白或一条分隔线，不变成三张全宽卡。 |

### 6.3 文章详情页头部

| 判断项 | 规则 |
|---|---|
| 结构描述 | 顺序为真实栏目或面包屑 → 标题 → 摘要 → 作者与日期 → 封面 / 证据图。标签若确有筛选价值，放在作者日期之后且最多 1 个。 |
| 视觉焦点 | 标题是唯一主角；摘要解释文章解决的问题；封面用于证据而不是再次显示标题。 |
| 信息弱化 | 日期、作者、阅读时长和标签均使用正文以下层级；不同时显示栏目、期号、页数、关键词、状态等一整排微信息。 |
| 是否保留大封面 | 有真实人物、场景、界面或结果物时保留 3:2 / 4:3 大图；只有通用插图或弱截图时宁可不放大封面。 |
| 一致视觉语法 | 延续首页的一处蓝色批注和真实证据；批注说明“本文值得关注什么”，不重复摘要。 |
| 内容上限 | 1 个栏目 / 面包屑、1 个标题、1 段不超过 80 个汉字的摘要、作者、日期、最多 1 个标签、1 张主图。 |
| 禁止模式 | 标题前堆 3 个以上标签、巨型英文分类、重复标题封面、渐变占位图、作者头像群、分享按钮抢占首屏、虚构 Issue。 |
| 桌面差异 | 标题与摘要共享稳定左轴；作者日期在其下。主图可在标题之后横跨内容宽度，或与真实批注形成非对称关系，但不套设备框。 |
| 移动差异 | 第一屏优先保留栏目、标题、摘要、作者 / 日期；标签可隐藏，主图放到首屏下方。标题最多三至四行，辅助信息不得挤压主张。 |

## 7. 禁止直接模仿清单

这些产品各自有成立的业务与视觉逻辑；问题不是它们的质量，而是直接借用后会掩盖 Midimily 的人、真实任务与小闭环。

| 产品类型 | 不适合 Midimily 的特征 | 最多可有限借鉴 | 避免最终像现成产品的方法 |
|---|---|---|---|
| Linear 风 SaaS 官网 | 黑色 / 高对比界面、产品窗口、功能动效、强操作感会把品牌变成协作软件 | 清楚的状态反馈与快捷阅读 | 不使用深色主面、命令菜单、悬浮产品窗和功能发布节奏；页面主角必须是中文判断和真实实践 |
| Vercel 风开发者网站 | 黑白大字、细网格、代码片段和部署语言会放大原 A 的模板风险 | 内容层级和文档可读性 | 不使用等宽装饰、终端、代码雨、黑底 Hero；蓝色批注必须对应人的任务而非系统状态 |
| Notion 风知识网站 | 文档图标、Emoji、块编辑器与数据库视图会把方案库变成个人知识库 | 清楚目录与稳定正文宽度 | 不复制页面图标、数据库表、折叠块外观；使用 Midimily 的真实案例、批注和界面证据 |
| Arc 风渐变科技品牌 | 饱和渐变、发光色、漂浮浏览器窗会重新制造抽象氛围 | 对人物使用场景的重视 | 禁用渐变与漂浮窗；真实界面保持平面裁切并说明任务关系 |
| Stripe 风抽象插图 | 复杂抽象图形、3D 设备与渐变常可替换到任何技术主题 | 图像与版式的主次关系 | 不复制几何母题；插图必须能说明文章的一个具体论点，并服从三色以内限制 |
| Apple 风产品大图 | 单一产品巨幅特写、舞台式滚动和材质表现不适合服务与内容并重的网站 | 一屏一个视觉主角 | 主角优先是观点、人物或证据，不是无上下文的设备；禁用滚动驱动产品拆解 |
| Bloomberg 风高密度信息 | 多列行情、强数据流和持续更新感会让内容难以进入，也不符合缓解焦虑的品牌人格 | 信息来源、时间和事实的严谨标注 | 不复制密集栅格、跑马灯和满屏数字；每屏仍保留一个清楚阅读轴 |
| The Verge 风强烈媒体视觉 | 超大标题、强对比色块和高频头条会让 Midimily 变成热点媒体 | 主次稿之间明确的编辑权重 | 不追逐头条排场；主稿必须连接到方法、案例或下一步，不用色块制造冲突 |
| Substack 风朴素博客 | 单列邮件流、作者中心和默认模板会弱化企业 / 个体双路径与方案产品 | 长文阅读宽度和订阅动作的克制 | 不复制作者头像 + 邮件订阅 Hero；保留服务路径、Web Deck 与证据型封面 |
| AI 创业公司通用 Landing Page | 紫蓝渐变、机器人、功能卡、客户 Logo、数字指标和双 CTA 会完全回到现有问题 | 首屏快速说明服务对象 | 用自然中文主张、两条文字路径和真实证据完成说明；不出现功能墙、假数据和氛围主视觉 |

统一防模仿规则：任何参考必须拆解成“它解决了什么信息问题”，只借问题解法，不复制其配色、字体组合、Hero 骨架、插图母题和动效组合。样板评审时若参与者首先说“像 Vercel / Notion / 某 AI Landing Page”，即判定品牌识别失败。

## 8. Codex 设计判断表

后续 Codex 在创建组件或静态样板前，必须逐项自检。

| 判断项 | 通过标准 | 失败表现 |
|---|---|---|
| 品牌识别 | 遮住 Logo 后仍能看到“小闭环”的叙事顺序、真实人物 / 情境、真实界面证据和一处蓝色编辑判断 | 只能识别为“一个蓝色 AI 网站”或“一个排版干净的内容站” |
| 编辑判断 | 每屏只有一个主角；主稿、次稿、摘要和元信息有明显权重差；批注说明为什么重要 | 所有内容等大，或依赖 `Featured / Latest / Issue` 宣布主次 |
| 人本表达 | 技术与具体人物、任务、场景或结果发生可说明的关系 | 只有产品 Logo、机器人、抽象图形、系统术语和界面框 |
| 图像信息价值 | 每张图至少贡献人物、情境、界面、结果或事件线索之一，并有必要图注 | 删除图片后理解完全不变，图片只是填充比例 |
| 卡片依赖 | 单屏完整包边容器不超过 2 个；连续区块不复用相同卡片骨架 | 标题、文章、步骤、证据和 CTA 全部卡片化，出现嵌套卡 |
| 英文装饰 | 英文只用于真实品牌名、产品名、通行术语或正式栏目名 | 删除英文不损失信息；出现装饰性全大写眉题、`Issue` 或伪代码标签 |
| 几何装饰 | 每条线、每个形状都能对应分组、标注、顺序或内容关系 | 出现漂浮圆形、节点、网格背景、无端连接线或光斑 |
| 移动端节奏 | 390px 下第一屏主张清楚、触控目标至少 44px、内容按重要性重排、关键动作不依赖 Hover、无横向滚动 | 把桌面多栏机械叠成超长卡片流，标签和元信息占满首屏 |
| 内容可读性 | 普通文字达到 WCAG AA 对比度；标题层级连续；正文约 30–36 个全角字符宽；图片和动效关闭后信息仍完整 | 浅灰小字、跳级标题、长行、文字压图、内容依赖图片内文字或动画出现 |
| AI UI 风险 | 29 项 AI UI 倾向中，单个方案最多命中 2 项低 / 中风险，且每项都有明确内容理由 | 同时出现大字、黑白亮蓝、细边框、空留白、英文微标签、虚构编号、几何背景或滚动动画中的 3 项以上 |

### 硬性停止规则

**如果某个设计同时符合三个以上典型 AI UI 特征，必须停止实现并重新设计。**

执行方式：

1. 在写组件前，用第 2 章逐项标出命中项；
2. 三项及以上时，不允许以“单项程度较低”为理由继续；
3. 先删除无内容作用的特征，再重做主次和证据关系；
4. 重新评审降到两项以内，且剩余特征都有真实信息职责后，才能进入实现。

## 9. 下一阶段静态样板的明确边界

下一阶段只制作以下三个**静态视觉样板**，每个同时提供 1440px 桌面版和 390px 移动版：

### 样板 1：首页首屏

- 验证一个中文主张、两条服务路径、一处蓝色编辑批注的层级。
- 可在首屏下沿出现一个真实实践入口，但不加入多文章、轮播、Logo 墙或完整导航状态设计。
- 使用仓库已有真实文案，不编写假客户、假数字或假期号。

### 样板 2：首页文章区第一屏

- 验证“一主两次”的非卡片结构，以及真实图像、标题、摘要的主次关系。
- 只选择 3 篇现有真实内容；不为视觉效果新增栏目、标签或统计数据。
- 至少输出一个“有可靠主图”版本；如素材不足，另做纯排版备选，不生成氛围占位图。

### 样板 3：文章详情页头部

- 选择一篇现有、证据最完整的文章，验证栏目、标题、摘要、作者 / 日期、封面与批注顺序。
- 封面必须使用获准的真实人物 / 场景、真实界面 / 成果，或明确标注为概念图解的材料。
- 不延伸到正文组件、推荐区、Footer 或 Web Deck 全页。

### 明确不在下一阶段范围内

- 不创建完整设计系统、Token 文件或组件库；
- 不设计全站所有页面、深层归档、Footer、筛选器和宠物完整状态；
- 不安装字体、图片工具或前端依赖；
- 不实现交互、滚动动画、响应式代码或生产组件；
- 不批量生成文章封面；
- 不修改现有网站；
- 不以“先实现再判断”跳过本文件的自检表。

三个样板通过的共同标准：五秒测试中，受访者能复述“Midimily 先从真实任务跑一个小闭环”，并能指出一处人物 / 情境证据与一处编辑判断；遮住 Logo 后，不优先联想到某个现成 SaaS、开发者网站或 AI Landing Page。

## 10. 校准总结

### 从原 A 方向中删除了什么

- 删除无真实发行规则的 `ISSUE 01 / 02` 与“本期目录”包装。
- 删除把三列视为偶尔可用默认布局的余地；首页两个样板区域完全禁止三列等宽卡片。
- 删除满屏可见网格的可能性；网格只作为构图方法，局部结构线必须有信息职责。
- 删除“知识切片”作为需要反复展示的品牌符号，避免用抽象知识语言包装普通文章。
- 删除以大字、细线、编号和黑白蓝本身构成品牌识别的假设。
- 删除图片裁切位移等没有信息作用的 Hover；交互只确认状态与关系。

### 保留了什么

- 保留 Swiss 作为唯一底层 anchor：白 / 中性浅灰、单一无衬线体系、左对齐、局部不对称与单一 Yves Klein Blue。
- 保留一屏一主角、主稿与次稿拉开权重、稳定阅读轴和大留白可作为叙事停顿的原则。
- 保留真实人物、过程、成果物与界面证据优先的图像策略。
- 保留企业 / 个体双路径、小闭环方法、方案库、Web Deck、GEO 证据关系和自然中文表达。
- 保留短促、可关闭、尊重 reduced-motion 的状态反馈。

### 新增的 Midimily 独有规则

- 主方向命名为 **Editorial Clarity × Human Observation / 编辑式清晰，人本式观察**，不再用 Swiss 代替品牌概念。
- 只保留“编辑批注、人物与技术并置、真实界面截取”三个视觉母题，并设定每屏 / 每文频率上限。
- 蓝色必须回答一个真实编辑判断或状态，单屏面积原则上不超过约 10%。
- 图像按“真实证据 > 真实情境 > 有依据图解 > 受限生成插图 > 无图”选择。
- 编号必须可追溯到真实步骤、时间、页码或栏目，禁止为版式虚构秩序。
- 如果同时命中三个以上 AI UI 特征，Codex 必须停止实现并重新设计。

### 当前仍存在的不确定性

1. 仓库内可合法公开使用的真实人物、工作场景、产品截图和成果物数量尚未完成素材盘点。
2. 哪一篇现有内容最完整地具备“问题—动作—结果—下一步”，尚需在静态样板前选择。
3. 现有暖白、蓝灰品牌色与 Swiss 白 / 中性灰 / 单蓝 token 的最终迁移范围尚未经过视觉样板对比；本阶段只锁定方向，不修改当前 `DESIGN.md`。
4. 小米立在主内容中的准确出现频率仍未验证；当前只确定它不能替代人物证据或 AI 图形。
5. 企业与个体两条路径在移动端的先后顺序是否需要固定，仍需结合真实访问与转化目标测试。
6. Phase 0 基线文档仍缺失，因此本文不对组件复用、技术债或实现工作量作额外推断。

### 下一阶段可安全制作的三个静态样板

1. 首页首屏：中文主张 + 两条服务路径 + 一处编辑批注；
2. 首页文章区第一屏：一篇主稿 + 两篇次稿的非卡片布局；
3. 文章详情页头部：标题、摘要、作者 / 日期、真实证据封面与一处批注。

只有这三个样板通过品牌识别、AI UI 风险、移动端节奏和内容可读性检查后，才进入组件或代码阶段。
