# Phase 3B-2：首页首屏静态样板审计

> 审计对象：`src/prototypes/home-hero/` 独立开发样板  
> 审计方向：**Editorial Clarity × Human Observation / 编辑式清晰，人本式观察**  
> 审计日期：2026-08-01  
> 审计方式：代码只读检查、1440 × 1000 / 768 × 900 / 390 × 844 浏览器实测、暖白 / 中性背景与小米立静态签名对照  
> 结论：**通过静态样板审计，建议进入人工视觉确认；不代表可以迁移到正式首页。**

## 1. 审计范围与证据

本次只审计首页第一屏，不包含正式 Header、Footer、文章区、导航逻辑和生产数据。样板使用 React 18 + Vite 独立 HTML 入口，不在 `App.jsx` 路由树内。

审计证据包括：

- 真实文案：中文主张、品牌解释、企业 / 个体两条内容观察路径和一处编辑批注；
- 代码结构：`HomeHeroPrototype.jsx` 与局部 `home-hero-prototype.css`；
- 视觉状态：暖白 A、中性 B、暖白 + 小米立静态签名；
- 响应式检查：1440px、768px、390px；
- 运行检查：生产构建、ESLint、控制台、横向溢出、链接尺寸和可见焦点样式；
- 临时截图：`/tmp/midimily-home-hero-phase3b2/`，不进入正式资产目录。

## 2. 三遍审计

### 2.1 第一遍：五秒感知与视觉层级

第一眼稳定落在“不只看趋势，先跑一个小闭环。”；摘要说明 Midimily 的观察对象与方法，企业路径在桌面占更宽阅读轴，在移动端先于批注和个体路径。没有图片、按钮组、数据或装饰图形与标题争夺注意力。

主标题是唯一绝对主角。标题在 1440px 和 390px 下均形成两行，中文标点与断句自然；没有依赖全大写英文、极端字重或抽象图形制造强度。

### 2.2 第二遍：阅读轴、品牌语法与响应式

- 桌面端：左侧主阅读轴承载品牌判断、摘要与企业路径；右侧窄轴承载批注和个体路径，形成有理由的非对称，而不是“左文右图”。
- 768px：标题和摘要保持单一阅读轴，路径区在首屏下半部展开；无横向溢出。小米立位于批注附近的空隙，不进入标题区域。
- 390px：DOM 顺序即视觉顺序，依次为标题、摘要、企业主路径、批注、个体次路径；侧栏自然降级为单列。实测两条路径高度约 132px 和 99px，超过 44px 基本触控要求。
- 编辑批注：只使用一条蓝色竖线和一句真实判断，没有卡片、气泡、引号海报或通知组件语义。
- 蓝色：主要承担链接、路径标题、编辑判断与分组规则，未形成大面积蓝底，视觉面积远低于首屏约 8% 上限。

### 2.3 第三遍：AI UI、模板感与可访问性风险

典型 AI UI 特征命中不超过两项：

1. **较大无衬线标题：低风险。** 字号仍服务中文主张，未扩张到全屏大字，也没有英文眉题、几何体或渐变与之组合。
2. **较多留白：低风险。** 留白把观点与两条内容路径分成“先判断、再选择”的节奏，不是为了制造空洞氛围。

细边线均承担分组或编辑标记职责，不计为无意义装饰。样板未出现渐变、发光、网格、玻璃、卡片阵列、胶囊标签、设备 mockup、虚构编号、英文微标签、双 CTA、订阅表单或滚动动画，因此未触发“三项 AI UI 特征同时出现即停止”的硬规则。

代码中链接与按钮均有 `:focus-visible` 轮廓；交互目标有明确文本名称。样板不含动效，`prefers-reduced-motion` 仍作兜底。浏览器控制台未发现 warning 或 error。

## 4. 暖白 A 与中性 B

| 判断项 | 暖白 A `#fcf8f2` | 中性 B `#f7faff` |
|---|---|---|
| 人本感受 | 更接近纸张和真实观察，降低“产品界面”感觉 | 更清醒、冷静，规则线对比稍清楚 |
| 品牌蓝关系 | 蓝灰文字在暖色底上形成温和张力 | 色相更统一，但更容易落入常见蓝白 AI / SaaS 内容站 |
| 与文章头部连续性 | 与已确认文章头部样板直接连续 | 可作为清洁度对照，但会削弱跨页背景连续性 |
| 图片兼容预判 | 真实照片更容易保持自然肤色与纸张感 | 产品截图会更清楚，人物照片可能略显冷 |
| 风险 | 若全站大面积迁移，可能偏米黄或降低某些图片边缘对比 | 容易把“编辑式清晰”误读成普通蓝白科技站 |

**建议：首选暖白 A 进入人工确认。** 它不是因为“更高级”，而是因为在同样的蓝灰排版下，能把主张从产品销售界面拉回人的观察与实践；中性 B 保留为对照，不建议在本轮推导为全局背景迁移结论。

## 5. 默认无小米立与静态签名态

| 判断项 | 默认无 | 小米立静态签名 |
|---|---|---|
| 主标题集中度 | 最强 | 不受明显影响；小米立远离标题并小于批注区文字块 |
| 品牌识别 | 依赖“小闭环”句子与双路径语法 | 增加一个现有品牌符号，遮住 Logo 时更容易回忆 Midimily |
| 人本 / 编辑关系 | 更成熟、纯编辑 | 增加陪伴感，但也可能被理解为吉祥物或 AI 助手 |
| 风险 | 视觉识别仍较依赖主文案 | 资源授权与正式角色定义尚需人工确认；若全站高频出现会削弱克制 |

小米立在本样板中**能提高识别，但不是结构成立的必要条件**。页面即使删除它，主张、摘要、企业主路径和批注仍完整；这证明品牌没有把内容价值外包给吉祥物。建议人工确认同时查看“暖白默认无”和“暖白静态签名”两版，在授权与角色边界确认前，不把签名态设为默认。

## 6. 关键问题回答

### 6.1 样板是否过度依赖“小闭环”一句话？

存在中等依赖，但不只依赖这一句。标题提供记忆钩子，摘要解释观察范围，企业 / 个体路径说明内容组织，批注把方法落到行动顺序。若未来替换标题，后三者仍能表达“真实任务—验证—复用”；但品牌辨识分预计会下降，因此下一阶段必须继续用真实文章与图像证据验证，而不能只靠文案保持辨识度。

### 6.2 双路径像内容观察路径，还是 SaaS 双 CTA？

当前更像内容观察路径。依据是：两者不等宽、不做按钮、不使用“立即开始 / 预约演示”等动作词，主路径说明流程、协作与交付，次路径说明个人工作流，并分别指向真实主题页。企业路径明显领先，避免了典型 SaaS 双主 CTA 的对称竞争。

### 6.3 是否像 Newsletter 模板？

风险低。页面没有居中单列标题、作者头像、订阅输入框、读者数量、Recent Issues 或英文 `Featured / Latest`。右侧批注与非对称路径也打破 Newsletter 默认骨架。

### 6.4 是否像通用 AI Landing Page 或 SaaS Hero？

风险低。没有左文右 mockup、双按钮、客户 Logo、功能卡、指标、机器人、渐变或发光节点。中性 B 的蓝白关系有轻微通用 AI 内容站风险，因此暖白 A 更合适。

## 7. 最明显的三个优点

1. **观点先于功能。** 首屏首先给出可复述的编辑判断，而不是产品口号、功能清单或热点集合。
2. **双路径主次真实。** 企业路径是首要观察入口，个体路径可发现但不抢夺；桌面和移动顺序一致。
3. **视觉语言克制且可迁移。** 暖白、品牌蓝、中文排版、规则线和批注与已确认文章头部样板有共同语法，又没有机械复制文章页双栏。

## 8. 最明显的三个风险

1. **结构识别仍弱于内容识别。** 遮住 Logo 并替换“小闭环”文案后，样板可能仍像优秀但通用的独立科技刊物。
2. **人本观察目前只有语言，没有证据。** 本轮禁止图像，尚未证明首屏与下一屏真实人物、任务或成果材料连接后仍能保持层级。
3. **小米立角色与授权未闭环。** 静态签名视觉上克制，但仓库资源的公开授权与它在正式内容中的角色频率仍需人工确认。

## 9. 人工确认建议

推荐先确认：

1. **主版本：暖白 A + 默认无小米立。** 用于判断排版、观点和双路径本身是否成立。
2. **对照版本：暖白 A + 小米立静态签名。** 只判断品牌识别提升是否值得角色与授权成本。
3. **背景对照：中性 B + 默认无小米立。** 只比较冷暖和科技站风险，不扩展为第三套视觉方向。

人工确认应回答：

- 五秒后能否复述“先跑一个小闭环”，并理解企业路径优先；
- 不看 Logo 时，暖白、蓝色批注、路径权重和中文主张是否足以联想到 Midimily；
- 小米立是恰当的品牌签名，还是让页面变得偏可爱 / 偏 AI 助手；
- 在 390px 第一屏内，摘要和两条路径是否仍有合适的呼吸感；
- 暖白是否应继续只用于样板，还是值得进入下一轮更大范围对照。

## 10. 审计停止点

本轮审计后不自动修改样板，不迁移正式首页，不进入文章区样板，不修改全局 token、Header、Footer、路由或内容模型。下一步仅在人工确认后决定是否保留暖白默认态、是否让小米立进入签名态，以及是否开始 Phase 3B-3。
