# Pattern：Editorial Story Group / 编辑文章组

## 目的

在同一屏呈现多篇内容时明确编辑取舍，证明无图、无卡片阵列仍能形成节奏。默认用于首页文章区第一屏，不等同于通用文章列表。

## 内容角色

- **Primary / 主稿：** 约 55%–65% 视觉权重；包含内容路径、标题、摘要和可选编辑批注。
- **Secondary / 次稿：** 约 20%–30%；包含内容路径、标题和短说明。
- **Tertiary / 收尾稿：** 约 10%–20%；以更小标题或观点入口收束，可带一条短说明。

三种角色不能使用相同字号、相同宽度、相同字段或相同容器。视觉权重是编辑关系，不机械换算面积。

## 数据与内容约束

建议展示层字段：

| 字段 | 角色 | 是否必需 | 来源/治理 |
|---|---|---:|---|
| `role` | primary / secondary / tertiary | 是 | 首页展示配置人工指定，不写入 Evidence 核心模型 |
| `editorialNote` | 主稿判断 | Primary 必需；其他默认无 | 可由 Evidence `finding` 起草，发布前人工编辑 |
| `shortDescription` | 角色化短说明 | 建议必需 | 从现有 summary/description 临时映射后人工缩写 |
| `contentPath` | 企业落地/个体成长等真实路径 | 是 | 由现有 topic/type 映射，禁止英文装饰 |
| `displayOrder` | 1/2/3 的内部排序 | 是 | 展示配置；除非是真实序列，不在 UI 显示数字 |

第一轮首页迁移前不修改 Evidence 数据模型。临时方案是在页面层建立一个只含 slug、role、displayOrder、editorialNote override、shortDescription override 的人工配置，并通过 slug 读取现有 Evidence。正式方案也应保持“证据数据”与“首页编辑编排”分离，字段可选性由角色决定，不把所有文章永久补齐同一组展示字段。

## 桌面结构

- 外层 1180px，暖白背景。
- 主稿位于约 760px 主阅读轴，次稿位于 240–300px 侧轴并下移，形成不同阅读速度。
- 收尾稿横跨下一行，以内容路径 / 标题 / 短说明的不同列宽收束。
- 主稿标题 48–61px；次稿 26–31px；收尾稿 20–24px。
- 只用字号、宽度、缩进、留白和发丝线分组；主稿不包卡片。

## 768px 重排

- 主稿先占满内容轴。
- 次稿降到其后并靠右，宽度最多约 62% / 430px，以保留权重差。
- 收尾稿可使用两列，但 DOM 顺序保持主稿 → 次稿 → 收尾稿。

## 手机重排

- 单列顺序：主稿 → 主稿批注 → 次稿 → 收尾稿。
- 主稿标题约 35–39px，次稿约 23px，收尾稿约 19px。
- 每段的字段仍不同；不得退化成三张同样卡片。
- 横向边距 20px，链接至少 44px 可触达。

## 图像边界

当前 pattern 无图成立。未来若加入真实证据，优先只给主稿：流程截图、工作现场、产品真实界面或前后成果记录，置于主稿摘要之后或作为下一屏过渡；不得同时为三篇补同尺寸缩略图。图片必须另行通过授权与图像语言审计。

## 交互

标题文本链接与简单文本入口即可。Hover 只下划线/变色，Focus 3px/5px，无整体卡片点击、上浮、箭头动画或自动轮播。

## 禁止

三列等宽、三篇等高、统一字段模板、图片区占位、热门榜、日期流、阅读量、Issue、英文微标签、每篇按钮或图标。

## 验收

- 第一眼确定主稿，第二眼发现次稿，第三眼看到收尾入口。
- 无图仍有三种阅读节奏；删除边框后仍能理解分组。
- 不像 Newsletter 日期列表、新闻门户缩略图流或 AI 内容卡片阵列。
- 真实内容更新后，长短标题仍保持角色而不靠手工截图断行。
